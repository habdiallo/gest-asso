## Pourquoi certains scénarios sont non applicables

- Les attributs du cookie de session et la signature du token ne sont pas
  observables depuis l'interface. Ils nécessitent un contrôle réseau autorisé,
  un test d'intégration backend ou des logs de développement expurgés.
- Les scénarios de l'espace personnel n'étaient pas exécutables avec le seul
  compte Administrateur du premier run. Un compte Membre de recette a ensuite
  été créé pour le run ciblé.
- Les scénarios propres aux rôles Trésorier, Opérateur et autres variantes de
  droits exigent des comptes de recette séparés, qui ne sont pas encore tous
  disponibles.
- Les indicateurs de préparation et de barème attendus dans la réponse API ne
  sont pas visibles dans ce parcours UI. Il faut les vérifier côté API ou par
  un test automatisé de contrat.
- Une expiration ou invalidation de session serveur n'a pas été simulée, afin
  de ne pas fabriquer une session invalide sans procédure de test documentée.

Un statut non applicable signifie donc non vérifié, et ne doit pas être compté
comme réussi.
